# 重做订单汇总

## 查找与核对

1. 定位用户指定的订单总表，检查工作表及实际表头。默认名称可参考“全部订单总和-副本.xlsx”，但不硬编码。
2. 按完整订单号精确匹配，核对“每日”“全部”及相关分表。数字部分只能辅助检索，不能独立证明关联；结合前缀、Customer Name、Order Name验证。
3. `RM12345(NA12345)`是明确关联号的格式示例，不是实际订单。若重做记录位于其他分表，可使用明确记录并在异常列注明位置和无法交叉核对的情况。不要将原订单多条材料明细误认为多份独立重做。
4. 多表字段冲突时保留共同可确认字段；冲突字段留空并注明表名、行号及差异。无明确依据时不挑选某一条、不按数字编造RM关联。
5. 每个输入订单一行，除非源数据明确有多个独立重做记录。未匹配也保留输入订单号和“未找到对应订单”。

## 固定12列

| 列 | 表头 | 填写规则 |
|---|---|---|
| A | Date | 对应订单原始日期，DD/MM/YYYY；不使用文件时间 |
| B | Customer Name-Remake | Customer Name加空格Remake，已有后缀不重复添加 |
| C | Customer Name-Order Name-RM Number-Remake | 新组合用Customer Name - Order Name - RM数字 - Remake；源表已有完整重做名称则保留原文 |
| D | RM Order Number (Original Order Number) | 从明确关联生成RM号(原订单号)，作为文本 |
| E | Blank | 数据保持空白 |
| F | 原始字段名1 | 原表四个对应字段的第一个值 |
| G | 原始字段名2 | 第二个值 |
| H | 原始字段名3 | 第三个值 |
| I | 原始字段名4 | 第四个值 |
| J | Blank | 数据保持空白 |
| K | Exception | 仅记录异常；正常留空 |
| L | OK Date | ok DD/MM/YYYY，执行当天之后的下一个工作日 |

先识别F至I的真实映射，不擅自选择四列。常见表结构为Color、Tilt Rod、Material、Material&Tilt Rod；实际不同则说明差异，映射不明时询问。内容原样复制，不翻译、汇总或重新计算；源值为空则目标为空。

日期按用户时区的实际执行当天动态计算，周一至周五为工作日，跳过周末；仅在用户提供节假日安排时一并排除。不得将历史执行日期写死在脚本中。日期缺失或无法解析时留空并记录。

## 输出

保存到订单源表所在文件夹：`Remake Order Summary_YYYYMMDD.xlsx`，重名加编号。一个工作表，名称`Remake Order Summary`。第一行表头加粗，自动筛选，合理列宽、边框、换行，数据区域不合并。保留可确认的原始数据类型。

验证恰好12列、E/J数据完全空白、顺序与输入一致、关联号有来源、重复记录有依据、OK日期符合实际执行日期。统计输入、匹配、未找到及异常订单数。
