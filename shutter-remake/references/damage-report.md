# Damage Report 提取与专业翻译

## 扫描

递归检查指定资料目录中的Excel、Word、PDF、图片及压缩包是否含Damage Report。只提取报告区域，不分析客户背景、无关表格、订单图纸或视频内容。可以读取同份报告中确定重做对象所必需的关联内容。

压缩包在独立临时目录安全解压，拒绝越出临时目录的路径；输出到压缩包原来所在文件夹。一个源文件有多份独立报告则逐份输出。识别已有生成结果，防止重复处理；不同来源的相同报告不应仅凭文本相同删除，应记录来源关系。

PDF、图片必要时用可用OCR。无法可靠提取时记录路径、原因、待确认内容，不生成虚假译文；不要把未检查的文件宣称为不含报告。

## 原文及中文结构

每份报告一份Excel，仅一个工作表`Damage Report`。完整英文报告位于上方，中文位于下方，两区留空行。

Excel来源优先复制报告原始单元格、格式、边框、合并关系与排版。只复制报告需要的内容，非报告工作表不带入输出。对公式保留可靠值或必要依赖，避免输出断裂引用。其他格式只提取报告，不转换无关内容。

中文区域只有两列：A标题“重做原因”、B标题“重做内容”；下一行A/B各一个内容单元格，禁止跨列合并或拆成多行。长内容在单元格内换行；设置边框、自动换行、足够列宽和行高。

只翻译以下两个字段，其他字段只保留英文：

- `Description Of Damage`：所有损坏情况放入“重做原因”一个单元格。不重复写Please remake等操作指令，不推断责任或未提及的原因。
- `Which Item is Damaged?`：结合本报告明确重做要求，确定“重做内容”。受损Item不等于整套Item都需重做。保留编号，不能擅自增加Panel、T柱或其他部件。

重做内容句式：`请免费重做【明确对象】，并安排海运发货。`。全部对象放同一单元格。范围无法确定时不要套用虚构指令：对象字段留空或标记“待人工确认”，在执行记录中说明缺失信息。原文只要求受损窗扇但未写Panel编号时可写“受损窗扇”，不补P1，并记录需确认编号。

## 行业术语

| 原文 | 中文规则 |
|---|---|
| Plantation Shutters | 透气窗 |
| tilt mechanism | 按上下文用内装置或齿轮拉杆，不用“叶片调节机构” |
| MECH | 保留缩写；上下文足够时译为内装置（MECH），否则标记需确认 |
| T-post 1 / T Post 1 | 第一根T柱，不用“1号T型中柱” |
| Panel 1 | P1或第一扇窗扇，保留编号 |
| Item 1 | 保留Item 1，不译为“项目” |
| Master、LTR、(L)(T)LTR | 保留原始标记，不自动当作独立重做对象，不扩写缩写 |

不确定术语保留英文并记录人工复核。示例仅说明术语，不可套用为真实报告内容。

## 保存与验证

保存在每份源文件原来的文件夹，命名`原始文件名_Damage Report_中英对照.xlsx`；多份报告增加01、02等序号，同名已有则另加不重复编号。

逐份核对英文全部内容、编号和结构标记未变；只有两个字段被翻译；损坏与操作要求分开；没有扩大重做范围；中文内容仅两个单元格；开头结尾符合要求（无法确认对象的异常报告除外）。记录输出路径、处理成功或待复核状态及任何读取失败。
